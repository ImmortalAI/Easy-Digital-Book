# AZW3 Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add direct AZW3 (KF8) export with a table of contents, cover, images, CSS, and popup footnotes for Kindle Paperwhite.

**Architecture:** `Book` passes through a shared pure preparation stage for documents and resources; separate serializers package the result as EPUB or KF8. The AZW3 writer follows our own binary format description, validated through experiments; Calibre is used for research and independent reading in tests only. The export dialog and controller select the writer while preserving existing file workflows.

**Tech Stack:** TypeScript, Vue 3, Pinia, shadcn-vue, novlang-js, fast-xml-parser, Vitest, Playwright; Calibre CLI and Python for CI verification only.

**Spec:** `docs/superpowers/specs/2026-10-03-azw3-export-design.md`; base architecture: `docs/superpowers/specs/2026-09-15-easy-digital-book-design.md`.

## Global Constraints

- Target **AZW3 (KF8)**; legacy MOBI 6, joint MOBI 6 + KF8, KFX, and embedded fonts are out of scope.
- The writer takes the **book model, not an EPUB file**. Extract the shared pipeline from the existing `services/epub/build.ts`.
- `services/azw3/` and the new `services/export/` contain pure functions, with no `vue`, `pinia`, or `@tauri-apps/*` imports; preserve the browser-global restrictions in `oxlint.config.ts` as well.
- Text records use PalmDOC (LZ77), **4096-byte record size**; `cdetype` = **`EBOK`**. Establish and document the remaining binary values in Task 1 rather than guessing them in this plan.
- Kindle Paperwhite preset: **1264×1680**, cover **1600×2560**; preserve the existing grayscale/titlePage/versionInTitle options for both formats.
- Determinism: **the same book and options produce the same bytes, except for the build date in EXTH**. With fixed `now`, output is entirely identical, including the PalmDB header and resource order.
- Calibre is a **test-only dependency, never a runtime one**. Export requires no shell commands or new Tauri capabilities.
- Popup footnotes require **a `noteref` link and a target that begins with a link back to the reference**. Endnotes provide the shared markup.
- Reuse existing libraries, platform services, and project helpers before implementing equivalents. Evaluate a new dependency against its actual API, license, maintenance, target runtime, determinism, cancellation, and the fixture requirements; document concrete gaps before choosing custom code.
- UI component priority is **shadcn-vue → Reka UI → custom**. First reuse `src/components/ui/`; if the required component exists in the shadcn-vue registry but is not installed, add it through the project-compatible CLI. Use Reka UI directly only when shadcn-vue has no suitable component. Write a custom primitive only when neither library provides it, recording the missing capability. Composing existing primitives into ExportDialog is application code, not a reason to reimplement their behavior.
- RU / EN / zh-CN: every new localization key exists in all three JSON files.
- The app writes a file to disk; USB transfer and Send to Kindle are out of scope. The `.edb` format stays unchanged.

## Review Focus

- UTF-8: Cyrillic, CJK, and emoji at the 4096-byte boundary; link positions use bytes rather than JS code units. Tests in Tasks 3, 4, and 7.
- Identical footnote IDs across chapters, repeated references, and unreferenced notes: unique addresses, a correct return to the first reference, and no fabricated backlink. Tasks 4, 7, and 10.
- Cancellation while packaging a large book and a format change while the save dialog is open: operation parameters remain fixed, and a cancelled export writes no file. Tasks 7–9.
- Images with identical basenames, WebP/GIF, CSS-only resources, and a missing cover: correct resource indices, supported actual MIME types, and optional offsets that never point to an unrelated record. Tasks 2, 6, and 7.
- Old/corrupt app settings, write failures, and repeated exports: EPUB fallback, atomic writes, processor disposal, successful retry, and correct Show in folder behavior. Tasks 8–9.

Confirmed upstream references: [shadcn-vue Select](https://www.shadcn-vue.com/docs/components/select), [Reka UI Select](https://www.reka-ui.com/docs/components/select), [fast-xml-parser](https://github.com/NaturalIntelligence/fast-xml-parser), and its [XMLBuilder documentation](https://github.com/NaturalIntelligence/fast-xml-builder/blob/main/docs/Builder_v1.md). Check the installed version's API rather than silently upgrading to match current examples.

The initial candidate search found [foliate-js](https://github.com/johnfactotum/foliate-js), a JavaScript reader/renderer with KF8 support, and [behringer24/azw3](https://github.com/behringer24/azw3), a Go writer. Neither establishes an available pure TypeScript writer matching this spec: reader support alone cannot produce AZW3, and a Go writer requires an additional integration/runtime decision. Task 1 must complete the capability assessment, including reusable PalmDOC/binary utilities and JS/TS writer candidates. Do not infer that no suitable library exists merely from this initial search. Prefer a suitable existing library behind the planned interfaces when one is demonstrated; otherwise document the gap and retain the spec's independent writer. Any integration that changes the pure-service/runtime architecture requires a corresponding spec and plan revision before implementation.
